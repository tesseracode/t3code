# Specification: copilot-sdk-runtime-upgrade

## Goal and sequencing

Establish one reproducible native Copilot SDK/runtime pair that preserves the
existing provider and exposes the routing contracts needed by Fusion. Qualify
this boundary before Fusion implementation; define Fusion alongside it.
SDK 1.0.28 is the initial candidate, not an already accepted release.

Follow-up authorization covers isolated implementation, dependency restoration
after manifest changes and focused qualification. The execution gates below
are not evidence that they passed or authorization to change live installations,
account policy or paid usage.

## Acceptance criteria

1. Select exact SDK/platform package versions and integrity identities. Verify
   published declarations, exports and runtime layout, not only GitHub main.
   Record the selected Node requirement and runtime version observed using the
   same flags as SDK startup. A normally auto-updated global CLI version does
   not qualify the bundled runtime.
2. Resolve the default runtime from its installed SDK-owned platform package.
   Preserve explicit binary, connection and environment overrides, home expansion,
   COPILOT_HOME/baseDirectory and per-instance isolation. Missing SDK, unsupported
   runtime and missing payload yield distinct actionable initialization errors.
   Do not silently substitute an ambient executable.
3. Keep `mode: "copilot-cli"`, subprocess isolation and native session IDs. New,
   resumed and cold-reconnected sessions retain the intended account/home and
   native conversation. Refuse concurrent ownership or forced replacement.
   Do not resume pending work automatically.
4. Preserve permission request IDs, the `no-result` callback handoff and
   authoritative applied-decision receipts. Failed/conflicting/foreign responses
   cannot report delivery success. Preserve user-input and plan handoffs without
   inventing native acknowledgements.
5. Root idle remains the successful turn-completion boundary; iteration, child
   idle and background/phase progress cannot terminate the root. Preserve
   cancellation, interruption, late-event exclusion, serialization and bounded
   teardown. Hidden generation retains its tools/config restrictions and
   idempotent cleanup across failures and interruption.
6. Existing explicit-model selection, supported reasoning efforts, text/tool
   rendering, skills, tasks, compaction and per-turn usage retain their semantics.
   Add no blanket approval or compatibility casts to hide protocol changes.
7. Built source-server output resolves the SDK from the actual emitted module
   location without a user-created symlink (#34). Source, desktop and standalone
   archives stage the qualified closure outside the bundle. Target-native wrapper,
   runtime library and required helpers remain present, executable where needed,
   and contained within the stage; asar-unpacked and Linux libc paths work.
8. Reassess old version overrides and payload allow/deny lists against the new
   artifact. The lockfile is regenerated by the package manager during
   implementation. Foreign/unused assets are removed only with target evidence;
   never reuse old pruning requirements merely by changing version constants.
9. Establish a supported typed way to obtain account-bound routing catalog
   metadata without starting a turn. Expose that capability to the Fusion child
   without synthesizing tiers, changing defaults or adding its UI here.
10. Release qualification includes actual intended targets: Mac arm64/x64,
    packaged Windows and WSL/Linux. Fixture/host-only success cannot stand in for
    target startup or native continuity. Mark unavailable gates unqualified.
    Preserve the old deployed release/profile and restore path; do not assume
    native-store downgrade compatibility.

## Minimal change boundaries

- Provider manifest and workspace lock/overrides.
- Provider client resolution/status plus only necessary adapter/generation API
  adaptation.
- Server external dependency ownership and desktop/archive staging.
- Focused existing provider and packaging suites; new cases only for changed
  behavior.

No Fusion timeline/picker, ACP, in-process migration, account selector, quota
reporting, context-tier UI or unrelated SDK feature exposure.

## Implementation and qualification gates

1. Read-only artifact check: validate registry integrity, CJS/ESM exports,
   declarations, native layout and modes. No install hooks or runtime execution.
2. Definition/exploration: identify the minimal owner-relative resolver,
   staging and API changes and explicit unresolved runtime questions.
3. After implementation authorization: complete tpatch implement/apply, regenerate
   dependencies, run focused provider/closure tests and targeted lint/typecheck.
   Test #34 from emitted server output, not merely the provider package cwd.
4. Separately scoped isolated runtime gate: no-inference handshake/catalog and
   copied/synthetic session checks with disposable state; then approved real
   continuity/approval/cancellation checks. Do not touch production account homes.
5. Packaged target gates and a recorded handoff to Fusion. No deployment until
   the intended target's evidence qualifies it.

The existing focused command selectors are listed in analysis.md. No repo-wide
checks or paid turns are part of definition/exploration.
