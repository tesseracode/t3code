ATT-01 / GitHub #3: add mutable current approval/input attention using fork migration 46 and an independent orchestration projector/cursor. Preserve the compact audit unchanged; implement only request state, replay, atomicity and explicit revert/import/delete policies, not ATT-02 awareness or ATT-03 RPC delivery. The maintainer approved extending this existing backend maintenance root to avoid invalidating it with an overlapping independent root.

ATT-02 / GitHub #4: extend the current attention projector with bounded awareness summaries and scoped failure/disconnect items. Preserve typed accepted provider lifecycle provenance on existing session-set events; no raw errors, client connectivity authority, RPC, UI or notifications. Matching provider recovery/completion and explicit revert/delete resolve lifecycle items; unrelated turns and seen state do not. The maintainer approved conservative unknown state without sufficient evidence and saturated summary counts with an overflow flag.

ATT-03/#5: authenticated owned attention.subscribe stream with bounded keyset bootstrap pages, separate signed page/delivery tokens, transaction-derived compact journal, gap-free catch-up/fence/live transition, generation/reset/overflow/expiry recovery and a shared client-runtime staging reducer. The maintainer approved one owned stream and a bounded derived journal instead of independent snapshot/stream RPCs. No UI, cross-environment aggregator, notification delivery, polling or new authoritative event log.

ATT-04 (#6): aggregate canonical attention in client-runtime through the existing environment registry. One owned subscription and fenced cache per enabled environment; scoped identities, explicit incomplete/live/stale counts, deterministic blocking-error then warning/oldest ordering, atomic per-environment reconnect, removal/disable/auth eviction, and shared web/desktop/mobile state exports. Relay hints stay advisory and never create items/counts; suppress them after a complete direct snapshot. Reuse capped connection backoff for recoverable stream resets; no sockets, polling, full thread loads, UI or notifications. Maintainer approved these policies during ATT-04 implementation.

ATT-06 prerequisite: expose derived current notification eligibility at the existing shared attention stream boundary. Retain accepted post-live item revisions and newly completed turns across UI batching; suppress snapshots/replay/rebuild, remove resolved/deleted candidates, and bound the map by current compact entities. This is local metadata only, without a notification sink or wire/server authority changes.

TWS-01 (#9): add narrow v1.2.14 public topology normalization, coalesced on-demand refresh, coverage/observation evidence, persisted optimistic-revision thread context and bounded typed commands/queries. The maintainer approved sticky explicit clear with a return-to-auto command, conservative stale/ambiguous source handling, registry-marker move identity, no name-only rename inference and no provider/TWS mutation. TWS is an optional integration: disabled by default per environment, with a Settings Integrations switch; disabled means no TWS CLI calls, cancellation of owned scans, inactive retained choices, and fresh observation required after re-enable. No generic plugin framework, polling, grouping UI or derived tags.
